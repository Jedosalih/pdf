# Internationalization — JPdf

## Locales

- `en` — English (default/fallback)
- `ar` — Arabic, **RTL**
- `tr` — Turkish

## Routing

Prefixed locale routing via `next-intl`: every route lives under
`app/[locale]/...`, e.g. `/en/merge-pdf`, `/ar/merge-pdf`, `/tr/merge-pdf`.
No un-prefixed default locale — this keeps canonical/hreflang generation
uniform and avoids ambiguity about which locale "/" serves.

`middleware.ts` (next-intl middleware) handles locale detection for `/`
(via `Accept-Language`, falling back to `en`) and redirects into the
prefixed path; it never rewrites silently in a way that breaks bookmarking
a specific-locale URL.

## Translation structure

```
messages/
  en/
    common.json      (nav, footer, buttons, generic errors)
    home.json
    tools.json        (shared tool-flow strings: upload, processing, errors)
    tool.merge-pdf.json
    tool.split-pdf.json
    ...
  ar/  (same file names)
  tr/  (same file names)
```

One namespace file per page/concern rather than one giant `en.json` —
keeps diffs small and makes it obvious which file a translator needs to
touch when a single tool page changes. `lib/i18n/request.ts` merges the
namespaces needed per route via `next-intl`'s `getRequestConfig`.

No component contains a literal user-facing string. Every string — including
error messages, aria-labels, and toasts — resolves through `useTranslations`/
`getTranslations`.

## RTL

- `app/[locale]/layout.tsx` sets `<html lang={locale} dir={locale === "ar"
  ? "rtl" : "ltr"}>`. This is the only place direction is decided.
- All spacing/positioning in Tailwind/CSS uses logical properties:
  `ms-*`/`me-*` (margin-inline-start/end), `ps-*`/`pe-*`, `start-*`/`end-*`
  instead of `ml-*`/`mr-*`/`left-*`/`right-*`. Tailwind v4's logical
  utilities are used by default — physical-direction utilities are only
  acceptable for properties with no directional meaning (e.g. vertical
  margins).
- Icons that imply direction (arrows, chevrons for "next/back") are
  mirrored via a shared `<DirectionalIcon>` wrapper that flips based on
  `dir`, rather than swapping icon components per locale by hand.
- Arabic typography uses Cairo; English/Turkish use Inter (see
  `docs/DESIGN_RESEARCH.md`). Font selection is driven by `<html lang>`,
  not per-component overrides.

## Locale-specific formatting

Dates, numbers, and file sizes are formatted via `Intl.NumberFormat` /
`Intl.DateTimeFormat` (through small helpers in `lib/i18n/format.ts`) keyed
off the active locale — never manually concatenated strings.

## SEO / hreflang

Every localized page (see `lib/seo/metadata.ts`) emits:

- `alternates.canonical` for its own locale/path
- `alternates.languages` with `ar`, `en`, `tr` (and `x-default` → `en`)
  pointing at the equivalent path in each locale

Content is translated per-page, not machine-translated metadata bolted onto
an English page structure — heading hierarchy and copy are written to read
naturally in each language (blueprint §28).

## Fallback behavior

If a specific namespace key is missing for `ar`/`tr`, `next-intl` falls back
to `en` for that key (configured fallback) so a missing translation shows
English text rather than a raw key — but missing keys are treated as bugs
to fix, tracked via a lint step (`scripts/check-translations.ts`, added once
the message set stabilizes) rather than accepted as normal.

## Locale switcher

A single `<LocaleSwitcher>` component swaps the locale segment of the
current path (preserving the rest of the route) so switching language
mid-flow (e.g. on a tool page) keeps the user in context instead of
bouncing to the homepage.
